# ATLAS AI 품질 평가 운영

기존 회원 UID를 `admin_users`에 등록하면 관리자 메뉴가 표시된다. SQL과 배포는 `deploy/AI_EVAL_SUPABASE.sql`, `AI_EVAL_ADMIN.sql`, `AI_EVAL_HERMES.md`를 따른다. 최초 등록/회수 후 권한은 매 요청 서버에서 확인하며 메뉴는 최대 30초 또는 창 포커스 시 갱신한다.

## 사용 순서
0. 사용가능 도구 → 데이터 종류별로 모델이 호출할 수 있는 도구와 API·DB 출처, 사용 조건, 질문 예시를 확인한다. 코드 등록 목록이며 운영 성공을 실시간 감시하는 화면은 아니다. 실시간 시세·DART 등 웹 기능에만 있는 데이터는 AI 미연결로 구분한다. 카탈로그는 `shared/agentToolCatalog.json`에서 관리하며 `ai_agent/tests/test_tool_catalog.py`가 실제 모델 도구 스키마와의 누락·중복을 검사한다.
1. 평가 질문 → 초기 30개 등록. 개선용 24개, 별도 확인용 6개. 사례의 성공 기준과 수동 평가 기준을 검토한다.
2. 사례에서 질문·대화·상태·검사 기준을 편집한다. 원본 회원 대화는 ‘평가 사례로 추가’ 후 필요한 맥락만 남긴다. 기본적으로 데이터 준비 필요 상태다. 합성 데이터에서 실제로 재현되는 사례인지 확인한 뒤 고정 데이터 v1을 지정한다.
3. 평가 실행 → 질문 선택 → 코드 검증 또는 실제 모델 평가 → 반복 횟수. 유료 모드는 명시적 체크와 실행 버튼이 필요하다. 동일 ID 재전송은 같은 실행을 돌려준다. 같은 조건으로 다시 평가하려면 ‘새 실행 ID 준비’를 누른다.
4. 실행 결과에서 질문별 출처·도구 입력·답변을 확인하고 수동 판정과 메모를 남긴다. 자동 실패는 수동 통과로 지워지지 않는다. 자연어 의미는 자동 통과 처리하지 않는다.
5. 변경 후 같은 사례·데이터·모델 설정으로 새 실행을 만들고 버전 비교에서 회귀를 확인한다. 비교 화면의 SHA/프롬프트·도구 해시를 함께 기록한다. 고정 데이터·모델 설정이 다르면 직접 비교 불가다.

## 검증 경계
- 사용가능 도구의 운영 확인 기록은 `shared/agentToolVerification.json`의 시각·대상 SHA에 한정된 운영자 전달 점검 결과다. 새로고침으로 운영 API를 검사하지 않는다. 2026-11-11 05:23:01 KST 기록은 일봉 읽기·뉴스 설정·알림 RPC 연결만 확인하며, 뉴스 수신·회원별 컨텍스트·실제 모델 응답 성공은 확인하지 않았다. 재점검 결과가 있을 때만 기록을 갱신한다.
- 코드 검증은 모의 응답으로 공통 Runner와 고정 시각 도구의 실행 경로를 확인하는 기본 점검이다. 질문 이해 평가가 아니며 결과는 검토 필요/품질 항목 해당 없음으로 표시된다. 세부 단위·통합 검사는 `node --test server/adminEval.test.js`와 `python -m pytest ai_agent/tests/test_evaluation.py` 및 기존 테스트에서 실행한다.
- 실제 모델 평가는 같은 Runner/SYSTEM/tools_schema/도구를 사용하고 데이터 공급만 격리한다. OpenAI 응답을 지정하지 않는다. 모델에게 채점 기준이나 모범 답안을 전달하지 않는다.
- 고정 데이터는 2026-10-28 08:00 KST 기준 4개 합성 국내 종목이다. 운영 시장/미국주식/실시간 데이터를 조사하는 평가가 아니다. 일봉은 2025-10-01~2026-10-27 완료 세션, 가격 하루 ±1, 고저차 10, 거래량 100이다. 삼성전자 ATR14=10, RSI14=0은 독립 수학 검산 기준이다.
- 고정 뉴스는 실제 Naver 호출 변환·기간 필터를 통과하는 합성 제목/요약이다. 외부 Naver 연결 상태 검증은 아니다.
- 실제 알림 응답 생성기를 격리된 메모리 저장소와 고정 날짜로 실행한다. 승인/거절 RPC·브라우저 버튼 검증은 별도 통합 테스트다. 이 항목은 자동으로 웹 검증 완료 처리하지 않는다.
- 모든 반복은 독립된 임시 DB와 상태로 시작한다. 운영 DB/브로커/카카오 쓰기 경로는 없다. code 모드와 live 모드를 합산하지 않는다.
- 초기 사례는 소규모 출발점이다. 모든 주식 질문을 대표하거나 실제 모델 성공률을 보장하지 않는다. 설명·자료부족/거절의 타당성·근거 충족은 관리자 판단이 필요하다.

## 비용·중단
동시 항목 1개. 실제 모델 항목당 추정 예산 $0.25를 원자적으로 예약한다. 잔액이 부족하면 대기 항목 취소. 사용량이 known이면 추정 사용액만 남기고, unknown/중단은 예약액을 보수적으로 유지한다. 모델 가격을 넘지 않는 청구 한도를 보장하는 기능이 아니므로 평가용 OpenAI 프로젝트의 별도 사용 한도도 관리한다. code 모드 0달러와 실제 호출 usage unknown을 구분한다.

대기 취소는 실행 중인 호출을 되돌리지 않는다. worker가 5분 heartbeat를 보내지 않은 항목은 interrupted가 되며 자동 재실행하지 않는다. 전체 작업 재시작은 관리자가 새로운 실행 ID로 명시적으로 수행한다. API→worker 작업 전달은 DB 큐를 사용하여 브라우저 새로고침과 HTTP 응답 유실에 영향을 받지 않는다.

## 기록·보존
케이스는 소유 관리자별 최대 300개, 실행은 한 번에 사례 30개×반복 3회. 최근 실행 100개를 화면에서 조회한다. 이전 실행·사례 버전은 자동 삭제하지 않는다. 결과당 200KB 미만, 입력 사례 24KB 미만으로 제한한다. 큰 실행 기록은 근거 요약으로 축소 표시한다. 비공개 추론/API 키/헤더는 저장하지 않는다. 관리자 본인 대화만 가져올 수 있다.

필요 시 결과 JSON을 검토·비식별화하여 내보낸 후 운영자가 보존 기간(권장 시작값 90일)을 정하고 종료된 실행만 정리한다. 아래는 **선택 작업**이며 마이그레이션에는 포함하지 않는다.

```sql
-- 먼저 삭제 대상 건수만 확인. 실행 여부는 운영자가 결정.
select count(*) from public.ai_eval_runs r where created_at < now()-interval '90 days'
and not exists(select 1 from public.ai_eval_items i where i.run_id=r.id and i.state in ('queued','running'));
-- 승인한 보존 정책에 따라 실행. items는 cascade 삭제, 사례 버전은 보존.
-- delete from public.ai_eval_runs r where created_at < now()-interval '90 days'
-- and not exists(select 1 from public.ai_eval_items i where i.run_id=r.id and i.state in ('queued','running'));
```

## 평가 기준 수정 예
자동 검사 JSON은 등록된 검사만 허용한다. 임의 코드·SQL은 지원하지 않는다.

```json
[{"type":"action","value":"watchlist_confirmation"},
 {"type":"rule","name":"threshold","value":200000},
 {"type":"no_mutation"}]
```

자동 통과는 구조적 검사 항목의 통과다. 전체 과업은 설명 의미까지 수동 검토해야 한다. 별도 확인용 질문을 보고 수정했다면 개선용으로 옮기고 새 확인용 사례를 마련한다. 개선 보고서는 실패 재현, 가설, 한정된 변경, 동일 조건 반복 실행, 회귀·비용·시간, 아직 확인하지 못한 운영 조건을 포함한다.
