# 개인설정 UI 모의 검증

`npx vite --config tests/support/vite.settings.config.js` 실행 후
`http://127.0.0.1:5184/tests/support/settings.html`을 연다.

실제 AccountSettingsModal/KakaoConnectionSection/SidebarFooter를 사용한다.
프로필·인증과 저장 API는 로컬 모의 서버로 격리하고 나머지 API는 차단한다.
env를 로드하지 않으며 운영 DB·회원·키·카카오·주문에 접근하지 않는다.
저장은 로컬 프로세스 메모리에서만 유지되어 새로고침·모의 계정 전환 복원을 확인할 수 있다.

- 초기 4개 미저장 → 모의 키 쌍 입력(체크 없음) → 저장 성공(저장됨).
- 기존 저장 후 수정 → 변경사항 미저장 → 검증 도구의 다음 저장 실패 → 기존 저장+입력 유지.
- 저장 성공 복원 → 삭제 체크(삭제 미저장) → 저장 → 해당 증권사 미저장.
- 닉네임만 저장할 때 settings PUT을 보내지 않는다. 요청 기록에는 필드명만 보이고 키 값은 출력하지 않는다.
- 숨겨진 텔레그램 값은 요청에서 빠지고 모의 서버에서도 보존된다. 실제 암호화 저장 경로는 server/accountSettings.test.js에서 별도 검증한다.
- 저장된 모의 키는 실제 연결 성공을 의미하지 않는다. 푸터는 연결안됨/사용불가로 유지하고 실제 검증 로직은 brokerConnections/accountConnections 기존 테스트로 확인한다.
- 도움말: 마우스 진입/이탈과 영역 이동, 클릭 고정/재클릭/외부 클릭, Tab/Enter/Space/Escape를 확인한다.
- 도움말 첫 Escape는 개인설정을 닫지 않고 폼 저장도 발생하지 않는다. IP는 선택 가능하다.

2026-11-14 Chrome 확인: 기본 1229×944, 390×844, 320×568; 양쪽 테마,
상태 순서·복원·실패·삭제·카카오 유지·텔레그램 제거·도움말 경계/키보드 확인.
계산된 저장 상태 글자 10px/500, 도움말 본문 12px/400.
모바일 폭 클릭은 검증했지만 실제 터치 기기와 운영 회원 저장/재로그인은 미검증이다.

초기 키 쌍 완성·항목당 4096자 제한은 프런트 입력 보호다. 잘못된 실제 인증 결과를 판정하지 않는다.
기존 서버 configured 필드는 저장된 쌍의 존재이고, 서버 암호화·인증·연결 검증·권한은 변경하지 않는다.
SQL/운영 컬럼/텔레그램 데이터 삭제 및 API/worker 재시작은 필요 없다.
