# 주식주문 화면 잘림 검증

## 재현과 원인

수정 전 실제 OrderEntryPanel을 사용한 로컬 화면에서 1366×768, NH 계좌 선택 + 매도 보유정보 상태를 재현했다.

| 요소 | 수정 전 DOM 높이 | 원인 관련 computed style |
|---|---:|---|
| .atlas-order-entry | 688px (scrollHeight 741px) | column flex, overflow:hidden |
| .side-tabs | 0px (자식 버튼 30px) | flex-shrink:1, overflow:hidden |
| .order-mode-tabs | 35px | 원래 지정 높이54px에서 축소 |
| .order-execute | 21px | flex-shrink:1 |

공통 스타일의 과거 높이 선언(패널690/루트688, viewport min-height718, 후속 height:100%)과 본문·선택 영역이 같은 flex 축에서 공간을 경쟁하는 구조가 겹쳤다. 같은 환경에서 매도와 NH 계좌/긴 안내는 필요한 높이를 더 늘렸다. 특정 노트북의 OS 배율이 원인이라고 단정하지 않는다.

## 수정

- 선택 영역은 flex:0 0 auto. 매수/매도/미체결 높이30px 유지.
- 일반·자동·미체결 본문을 order-body-scroll로 분리. 입력값·계산·권한·요청 로직과 key는 변경하지 않았다.
- 충분한 화면(너비1051px 이상, 높이801px 이상)은 남은 높이의 본문에서 스크롤. 주문 버튼44px 유지.
- 너비1050px 이하 또는 높이800px 이하는 세로 배치/자연 높이/페이지 스크롤. 낮은 화면에서 지표 목록이 한 입력칸보다 작아지는 상태를 피한다.
- 미체결 표는 수평 스크롤을 유지하며 별도 세로 높이 제한을 제거해 본문과 세로 스크롤이 중복되지 않는다.
- 지표 목록의 기존 내부 스크롤은 유지한다. 실험실의 과거 min-height600과 중복 주문 높이 선언을 정리했다.
- 새 본문 영역은 키보드 포커스 가능하고 focus-visible 표시를 제공한다. 주문 확인/관리 모달은 기존 portal을 유지한다.

## 실행 방법

```powershell
npx vite --config tests/support/vite.orderLayout.config.js
```

Chrome에서 http://127.0.0.1:5182/tests/support/orderLayout.html 을 연다. 이 config는 env 파일을 로드하지 않으며, 조회/주문 서비스만 로컬 fixture로 대체하고 /api 요청도 차단한다. 실제 API/주문·정정·취소는 호출하지 않는다. production 빌드의 진입점은 변경하지 않았다.

## 실제 브라우저 검증 범위

Chrome viewport override로 다음 CSS viewport를 실제 렌더링했다. **125/150%는 확대 시 줄어드는 유효 크기를 계산한 검증이며 Chrome 자체 확대 성공을 뜻하지 않는다.** 브라우저 키 입력으로 확대를 시도했으나 DPR/viewport 변화가 확인되지 않았다. Windows 배율은 변경하거나 검증하지 않았다.

| 기준 크기 | 기준 viewport | 125% 상당 | 150% 상당 |
|---|---|---|---|
|1366×768|1366×768|1093×614|911×512|
|1536×864|1536×864|1229×691|1024×576|
|1920×1080|1920×1080|1536×864|1280×720|

- 아홉 크기에서 네 증권사 변경/매도 탭: 선택 탭30px·버튼44px, 페이지 가로 넘침 없음.
- 아홉 크기에서 NH 계좌 선택, 매수/매도/미체결, 긴 오류, 빈 목록/16개 주문, 주문/지표 전환 및 실험실 지표 설정 확인.
- 최종 아홉 크기에서 주문·실험실 지표 목록의 높이는 최소112px 이상이었으며 목록1818px를 내부 스크롤로 접근했다. 작은 viewport에서는 목록323px, 페이지 스크롤을 사용했다.
- 미체결 표의 clientHeight와 scrollHeight는 둘 다1286px: 표 자체의 세로 스크롤 없음. 데스크톱 본문은 필요한 경우 세로 스크롤, 작은 화면은 페이지 스크롤을 사용했다.
- resize 이후 가격71000·수량2·NH 선택계좌2·매도 상태 유지 확인. 기존 증권사/계좌 변경에 따른 입력 초기화 규칙은 그대로다.
- 일반/자동 본문, 키보드 스크롤, 하단 주문 버튼 접근, 주문 확인 portal 및 관리 portal 위치 확인. 확정 버튼은 누르지 않았다.
- 390×844, 라이트/다크, 게스트 안내, 마지막16번째 주문의 포인터/Enter 조작과 모달/Escape 확인. 페이지 가로 넘침 없음.

미검증: 실제 Chrome125/150% 확대, 다른 Windows 배율/노트북 실기, 개인 계좌 기능 및 실제 차트 데이터. 모의 화면 검증을 실계좌 검증으로 보고하지 않는다.

프로덕션 코드는 OrderEntryPanel.jsx/styles.css/lab.css만 변경했다. 서버·API·DB·권한·유량·중복 방지·AI 변경 없음. VPS 작업 없음.
