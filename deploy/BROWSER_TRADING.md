# 자동매매 화면의 브라우저 실행

이 변경의 App 진입점은 `BrowserTradingAgentPanel`이다. 기존 LIVE API, 주문 gateway, worker, 권한 검증은 그대로 보존하며 이 화면의 저장·시작·정지는 해당 경로를 호출하지 않는다. 모든 로컬 설정·실행·거래에는 `BROWSER_SIMULATION` 모드와 회원 범위가 있다. 가상 거래에는 증권사 주문번호·체결번호가 없다.

## 데이터와 실행

- 기존 관심종목(최대 20개)과 저장 전략 목록을 재사용한다. 새 설정·전략 스냅샷·거래 결과는 회원별 `atlas.browser-trading.v1:<userId>` 브라우저 저장소에 보관한다. 서버의 LIVE 설정·거래 테이블에는 쓰지 않는다.
- 증권사별 내부 운용 자금은 각각 10,000,000원이며 같은 증권사의 실행은 잔액을 공유한다. 실제 계좌의 현금·보유분은 조회하거나 사용하지 않는다. 수수료·세금·슬리피지는 반영하지 않는다.
- 차트는 기존 `/api/public/market/<broker>/candles`의 기본 15분봉이다. 기존 KB→키움 대체만 허용하고 실제 출처를 표시한다. 지표는 시작 당시 전략 스냅샷이다. 차트 준비 봉은 최대 500개이며 부족하면 오류로 표시한다.
- 진입 조건 판단은 차트 주기와 분리된 기존 공개 일봉 DB(`/api/public/lab/candles?symbol=...`, 선택 종목만)와 `/api/screener`의 확정 기준일을 사용한다. 판단용 일봉은 최대 2,000개다. 품질·준비 봉·기준일 검증 실패는 대기/오류로 처리한다.
- `/api/public/market/session`의 검증된 KRX 정규장에만 평가한다. 선택 증권사의 최근 1분봉 종가·원본 시각이 유효하고 90초 이내일 때만 내부 진입·청산을 계산한다. 봉 시각과 가상 처리 시각을 따로 저장한다. 실제 개별 체결가·체결시각으로 주장하지 않는다.
- 화면이 보이는 동안 10초마다 최대 2개 실행을 순환 평가한다. 차트는 15초마다 갱신한다. 같은 봉은 교체하고 거래량을 반복 합산하지 않는다. 시세 조회 사이의 가격 도달은 놓칠 수 있다.
- 화면 이탈·비활성화·로그아웃·사용자 변경·재접속은 실행을 정지시킨다. 놓친 기간을 재생하지 않으며 자동 재시작하지 않는다. 정지한 포지션은 기록과 사용 자금을 보존하고 자동 청산하지 않는다. 이 저장소는 기기/브라우저별이며 회원 간 동기화 기능이 아니다.

## 촬영 순서

1. 로그인 후 관심종목과 익절·손절 및 지표가 설정된 전략을 준비한다.
2. AI 에이전트 → 자동매매 에이전트 → 설정에서 증권사·전략·수량·최초 실행 방식을 고르고 항목 체크 후 저장한다.
3. 실행에서 저장한 항목을 개별 시작하거나 체크 후 선택 시작한다. 저장만으로 시작되지 않는다.
4. 진행상황에서 시작한 종목의 15분봉, 전략 지표, 아래 상태·결과를 확인한다. 여러 종목은 좌측 버튼으로 전환한다.
5. 진입 조건 미충족·장 종료·데이터 오류이면 해당 상태를 그대로 촬영한다. 결과 생성을 강제하지 않는다. 개별 정지 또는 화면 이탈로 실행을 멈춘다.

제품 화면에는 요청에 따라 모드 배지·워터마크를 표시하지 않는다. 촬영물을 외부에 설명할 때는 브라우저에서 계산한 가상 결과이며 실제 주문 실적이 아니라는 구현 범위를 정확하게 설명한다.

## 격리 검증과 배포

```powershell
node --test tests/browserTrading*.test.js tests/tradingManagement.test.js tests/tradingPresentation.test.js tests/purchasePriceLine.test.js
node node_modules/vite/bin/vite.js --config tests/support/vite.browserTrading.config.js
# http://127.0.0.1:5187/tests/support/browserTrading.html
npm run build
```

격리 화면은 실제 컴포넌트·엔진·읽기 어댑터에 고정 시계·모의 시세를 주입한다. 외부 fetch는 모두 실패시키며 운영 계정·개인 키·실주문·카카오·유료 AI를 사용하지 않는다. 검증 도구는 제품 진입점에 포함되지 않는다.

프런트엔드 변경만 있다. main 푸시 후 Vercel 프런트 자동 배포 대상이며 VPS 코드 반영·서비스 재시작·환경변수·의존성·Supabase SQL 작업은 없다. 기존 LIVE 활성화 플래그와 무관한 worker·일봉 DB를 변경하지 않는다. 프런트 장애 시 직전 정상 Vercel 배포로 복귀하며 가상 기록과 운영 LIVE 데이터는 삭제하지 않는다.
