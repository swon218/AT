# 자동매매 V2 검증 기록

2026-11-16, D:\AT. 운영 회원·운영 DB·실제 증권사 주문을 사용하지 않았습니다.

## 자동 검증

- 전체 서버 테스트와 프로덕션 빌드를 실행했습니다. 최종 개수는 커밋 전달 결과에 기록합니다.
- 토스 실제 어댑터/전송 클라이언트/엔진을 고정 HTTP fixture와 durable store double로 연결했습니다. 누적 부분체결, crash 후 재적용, 취소의 새 ID, 비동기 취소 거부, 접수 응답 전체 유실, 느린 preflight 중 정지·lease 만료, 두 worker 경쟁을 검증했습니다.
- NH는 본인 계좌·현금 한도·보유·시세·개인 차트·주문/취소 번호 정규화와 쓰기 전송 0을 확인했습니다. 복구 미확인 계약을 구현 완료로 취급하지 않았습니다.
- 새 실행 상세의 인증·소유권·Origin·민감 필드 제거, V2 저장소 marker, 정책 위조 거절, 기존 키움 스냅샷 호환, 증권사별 epoch·계좌 목록 중 자격증명 교체 경쟁을 확인했습니다.
- PGlite에서 V1→V2 적용/재적용, 기존 세션·체결·불명 intent·번호 매핑 보존, 소유권·RLS·직접 권한 차단, 실제 기존 자격증명 CAS를 통한 네 증권사별 epoch 삭제/재등록 격리를 확인했습니다.
- 별도 PostgreSQL 17 임시 로컬 cluster에서 독립 psql 세션으로 전략 저장 중 FOR SHARE 잠금 대기와 두 건의 600원 예약/1000원 잔고 경쟁에서 한 건만 성공하는 것을 확인했습니다. 임시 cluster는 종료·제거했습니다. 운영 Supabase RLS 확인을 대신하는 결과는 아닙니다.

## 실제 Chrome / 격리 UI

`tests/support/trading.html`의 실제 TradingAgentPanel·TradingViewChart와 모의 API를 사용했습니다.

- 설정의 증권사/계좌 변경→선택 저장→읽기 전용 실행 카드 반영, 미저장 구분, 실행 화면 canvas=0.
- 세 증권사 연결/지원 fixture 선택. 별도 NH 제한 fixture 적용 시 NH 실행/체크박스 비활성, 전체 선택은 키움·토스만 포함.
- 모의 일괄 실행 확인창에서 SOR/공급자 시세 설명 확인. 모의 시작 후 한 종목만 정지하여 다른 실행 유지.
- 진행상황 최초 진입 우측 미선택, 실행 ID별 같은 종목의 정지/완료 이력 구분, 선택한 토스 개인 차트 및 부분체결/보유·평균가선·결과 표시.
- 응답 지연 fixture에서 키움→토스 빠른 선택 뒤 마지막 토스 실행과 차트/결과 유지.
- 원본 전략 수정 후 활성 실행은 원래 v1 스냅샷 유지, 정지된 저장 설정은 재저장 필요 표시.
- 20개 목록의 카드/버튼 및 페이지 스크롤. 1366×768, 1536×864, 390×844에서 페이지 가로 넘침 없음. 1093×614, 911×512의 작은 유효 viewport에서도 가로 넘침 없음. 모바일에서는 목록·차트 세로 배치, 라이트/다크 대비 확인.
- **1093×614 / 911×512는 125%/150% 확대와 비슷한 유효 viewport 검사이며 실제 Chrome 확대율 또는 Windows 배율 검사가 아닙니다.** OS 배율과 실제 125%/150% 확대, 모든 키보드/스크린리더 조합은 미검증입니다.

화면 증거: 사용자에게 최종 전달한 `trading-v2-progress.png`는 모의 토스 진행상황입니다. 실제 계좌 수신 증거가 아닙니다.

## 수행하지 않은 검증

실제 개인 키/실계좌 응답 대조, 토스/키움 모의투자 서버 또는 실주문·취소, NH 실행 복구, 운영 SQL 적용, 운영 LIVE/worker 활성화, 회원 키 변경, 카카오·유료 AI 호출. 배포 자체가 실거래 지원의 실검증 완료를 뜻하지 않습니다.
