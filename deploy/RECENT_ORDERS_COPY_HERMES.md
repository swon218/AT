이번 변경은 `codex/dashboard-orders-only`의 **최근 주문 조회** 커밋입니다. 기준 SHA는 `250d53454aee56911672c520917a737ac2abd711`이며 사용자가 전달하는 최종 전체 SHA를 적용하세요. `main` pull/merge나 실험실 변경을 포함하지 마세요.

## 반영 범위

- 최근 주문 카드의 증권사 API 미등록 안내·개인 설정 버튼, 단일 계좌의 증권사·계좌 설명, 증권사별 조회 실패 안내를 제거합니다.
- 선택한 증권사 중 등록된 증권사가 하나 이상 있고, 등록된 곳이 모두 정상 조회됐으며 결과가 0건이면 **최근 거래 내역이 없습니다**를 표시합니다. 미등록 증권사가 함께 선택됐다는 이유로 정상 빈 내역을 숨기지 않습니다.
- 성공한 내역이 있으면 표를 유지합니다. 빈 결과에 조회 실패가 포함되면 **거래 내역을 불러오지 못했습니다.**, 계좌 선택이 필요하면 **조회 계좌를 선택해주세요.**, 전부 미등록이면 **조회 가능한 증권사가 없습니다.**로 구분합니다. 실패를 거래 없음으로 표시하지 않습니다.
- 여러 계좌 중 조회 대상을 고르는 선택창과 주문 상세의 계좌 구분은 유지합니다. 0~4개 선택·전체 해제 안내·최근 5건 정렬·더보기 준비 중·350ms 선택 묶음·서버 중복 방지는 유지합니다.
- 키움 조회 실패 자체를 고치는 변경이 아닙니다. 기존 안전한 서버 오류 기록과 429 대기 처리를 유지합니다.

## 검증 및 배포

**프런트엔드만 배포하면 됩니다. VPS 코드 반영·서비스 재시작은 필요하지 않습니다.** 기존 `250d534` Node API와 호환되며 서버·Python·DB·환경변수·의존성 변경은 없습니다. VPS SHA와 Vercel SHA가 다른 이유를 프런트 전용 변경으로 보고하세요.

별도 staging checkout에서 사용자 전달 SHA를 확인합니다.

```bash
git fetch origin codex/dashboard-orders-only
git switch --detach "$DEPLOY_SHA"
git merge-base --is-ancestor 250d53454aee56911672c520917a737ac2abd711 HEAD
git log -1 --format='%H %s'
git diff --name-only 250d53454aee56911672c520917a737ac2abd711 HEAD
node --test tests/recentOrders.test.js tests/assetSummary.test.js
npm run build
```

로컬 검증은 관련 테스트 **7/7**, 프런트 빌드 성공입니다. 모의 브라우저에서 KB 미등록 + 등록 3사 정상 0건의 빈 문구, 부분 실패 중 성공 내역 유지와 안내 문구 제거, 다중 계좌 선택, 단독 실패의 일반 오류, 전체 해제를 확인했습니다. 실제 증권사 추가 호출이나 실주문은 하지 않았습니다.

Vercel의 해당 최종 SHA Preview가 Ready인지 확인한 후 **동일 SHA를 Production으로 승격**하세요. `main` 배포는 승격하지 마세요. Vercel 인증이 없으면 Preview ID와 승격 필요 여부를 사용자에게 전달하고 VPS를 재시작하지 마세요. 완료 보고에는 실제 Production SHA·새 배포 ID·운영 도메인을 포함합니다.

화면 검증은 우선 모의 환경을 사용하세요: `node tests/recentOrdersBrowserHarness.mjs` → `http://127.0.0.1:15176/tests/recentOrders.html`. ‘KB 미등록 · 등록 증권사 정상 0건’과 ‘KB 조회 실패’ 시나리오가 있습니다. 마친 후 모의 서버를 종료하세요. 운영 증권사 반복 조회로 검증하지 말고, 실제 키움 오류 조사는 기존 별도 진단 절차와 구분하세요.
