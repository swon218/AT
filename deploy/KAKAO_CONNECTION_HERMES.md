# ATLAS 카카오 계정 연결 운영 반영

1. 사용자가 전달한 `main`의 ‘카톡 연결’ 전체 SHA를 대상으로 합니다. ATLAS 인증용 Supabase SQL Editor에서 대상의 [KAKAO_CONNECTION_SUPABASE.sql](KAKAO_CONNECTION_SUPABASE.sql) 전체를 관리자 권한으로 먼저 적용하고 마지막 확인 쿼리 두 개의 기대 결과를 확인한 뒤 진행하세요. DB를 초기화하거나 기존 증권사 설정을 수정하지 마세요.
2. Kakao Developers에서 ATLAS 전용 앱의 카카오 로그인을 활성화하고 REST API 키에 `https://srv1826612.tail6bd3f3.ts.net/api/account/kakao/callback`을 그대로 등록하세요. 끝 슬래시, 쿼리, Vercel 주소를 붙이지 마세요. Client Secret을 활성화하고 사용하지 않는 개인정보·친구·메시지 동의 항목과 OpenID Connect를 설정하지 마세요. 어드민 키는 카카오 로그인에 필요한 API만 허용하고, 가능한 경우 VPS의 실제 외부 송신 IP로 제한하세요. 테스트 앱이라면 검증 사용자를 앱 멤버로 추가하세요.
3. 현재 서비스의 경로·실행 사용자·환경파일을 확인하세요. 기존 운영 경로는 `/opt/atlas`, 실행 사용자는 `atlas`, Node 환경파일은 `/etc/atlas/atlas.env`입니다. 기존 값은 보존하고 `KAKAO_REST_API_KEY`, `KAKAO_CLIENT_SECRET`, `KAKAO_ADMIN_KEY`, `KAKAO_REDIRECT_URI` 네 변수만 추가하세요. 마지막 변수 값은 위 콜백 URI입니다. `FRONTEND_ORIGIN=https://at-chi-six.vercel.app`, 기존 Supabase 서버 설정, `ATLAS_CREDENTIAL_ENCRYPTION_KEY` 및 Vercel의 `VITE_API_BASE_URL=https://srv1826612.tail6bd3f3.ts.net`을 확인하고 유지하세요. 키는 서버 환경파일에서만 관리하며 채팅, 로그, Vercel·`VITE_*` 변수에 복사하지 마세요. 인가 리다이렉트의 REST 키는 OAuth의 공개 `client_id`로만 쓰입니다.
4. 기존 HTTPS 경로에서 `/api/account/kakao/*`를 원래대로 VPS에 전달하세요. `/authorize`·`/callback`의 쿼리 문자열을 접근 로그·트레이스·분석에 남기지 말고 해당 경로의 응답을 캐시하지 마세요. 팝업의 호스트 전용 `Secure; HttpOnly; SameSite=Lax` 쿠키와 `Set-Cookie`를 전달하세요. API fetch는 운영 출처 CORS와 Supabase Bearer 인증을 사용하며 교차 출처 자격증명 쿠키를 추가하지 않습니다. 콜백의 `postMessage` 대상은 운영 출처 하나이며 팝업이 분리되면 원래 화면의 인증된 상태 조회로 완료합니다. Tailnet이나 브라우저의 로컬 네트워크 제한은 기존 접근 권한을 따릅니다. 검증을 위해 API를 공개하거나 CORS를 `*`로 바꾸지 마세요.
5. 운영 Git 작업 트리가 깨끗한지 확인하고 이전 정상 VPS SHA, 환경 설정의 안전한 백업 위치, 직전 정상 Vercel Production 배포를 기록하세요. 서비스의 Node에서 `node -p "JSON.parse('9223372036854775807', (_k, _v, c) => c?.source)"`가 숫자 원문을 그대로 반환하는지 확인하세요. `git fetch origin main` 후 전달받은 SHA가 `origin/main`에 포함되고 현재 VPS HEAD의 후속인지 확인하세요. 현재 HEAD부터의 실제 서버 diff를 확인하고 다른 미반영 기능이 섞여 있으면 임의로 반영하지 마세요. 기존 checkout에서 `git merge --ff-only <대상-SHA>`로 반영하고 `atlas-api.service`만 재시작하세요. 의존성 변경, AI/실험실/DART 재시작 또는 새 타이머 설치는 이 기능에 필요 없습니다. 배포 순서는 SQL → 환경과 VPS API → 대상 SHA의 Vercel Production 및 운영 UI 검증입니다. `main` 푸시로 Vercel이 먼저 배포됐더라도 SQL·VPS가 준비될 때까지 카카오 기능은 사용할 수 없습니다.
6. loopback과 기존 HTTPS API에서 `/api/health` 200, Bearer 없는 `GET /api/account/kakao`와 `POST /api/account/kakao/{start,check,unlink}`의 401, 임의 상태의 콜백 400을 확인하세요. 운영 출처만 CORS가 허용되는지 확인하고 상태 코드만 기록하세요. Vercel 배포 SHA·Production 상태·운영 도메인을 확인하세요. 운영 브라우저에서 본인이 동의한 계정으로 개인설정 연결, 마스킹된 ID·연결일, 연결 확인, 인증 취소 후 초안 유지, 카카오에서 먼저 해제한 뒤 상태 확인, ATLAS에서 연결 해제를 검증하세요. 카카오 계정 설정에서 앱 연결이 해제됐는지도 확인하세요. 실제 계정이나 브라우저 접근이 없으면 해당 항목은 미검증으로 보고하세요. 주문·알림은 보내지 말고 로그·스크린샷에 쿼리, 쿠키, 계정 ID, Authorization, 비밀값을 남기지 마세요.
7. 이상이 있으면 카카오 변수 네 개만 제거하거나 이전 환경을 복원하고, 기록한 이전 정상 VPS 코드로 되돌린 후 `atlas-api.service`만 재시작하세요. 기존 VPS health와 비인증 차단을 확인하고, 필요하면 Vercel도 직전 정상 Production으로 되돌리세요. 기존 증권사·텔레그램 설정과 새 카카오 테이블은 보존합니다. SQL 적용, VPS SHA, 프런트 배포, 실계정 테스트를 별도로 보고하세요.

카카오 연결 해제 웹훅은 설치하지 않습니다. 카카오에서 먼저 철회하면 개인설정을 열거나 ‘연결 확인’을 할 때 발견하며, 직전 정상 확인은 최대 60초 재사용합니다. 만료된 OAuth 요청은 새 연결 시작 시 정리합니다. 필요하면 SQL 파일의 관리자 전용 정리 쿼리를 실행할 수 있습니다.
