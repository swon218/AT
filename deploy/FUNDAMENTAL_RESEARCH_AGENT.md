# 기업·공시·재무 조사 담당

`fundamental`은 동일한 운영 모델과 ResearchGraph, 전체 8회 모델·12회 도구·40,000토큰·$0.25·120초 기본 예산을 사용한다. 독립 조사 최대 2개, 위임 배치 최대 2회는 그대로다. 뉴스·일봉·시세와 결합해도 별도 예산을 만들지 않는다.

## 실제 데이터 경로

Python `ResearchTools` → 고정 loopback 인증 `/api/internal/agent/data` → Node `agentResearchData` → `agentFundamentalData` → 기존 `companyDart.read` → Supabase DART 매핑·작업 스냅샷. Node가 running 요청 소유권과 내부 인증을 검사한다. Python이나 모델에 DART·브로커·Supabase 비밀키를 전달하지 않는다. Vercel 공개 프록시는 내부 경로를 노출하지 않는다.

AI는 **저장 스냅샷만 읽는다**. `refresh:false`로 기존 자료를 재사용하며 모델 요청의 예산 밖에서 DART 수집 작업을 시작하지 않는다. 저장되지 않은 기업/기간/페이지는 `dart_data_not_collected`, 매핑 미지원은 `dart_company_mapping_missing`, DB·권한·제한 오류는 각각 오류로 반환한다. 실제 빈 조회 결과와 구분한다. 해당 범위가 필요하면 기존 기업 분석 화면에서 조회·수집한 뒤 기존 갱신 정책을 이용한다. 새 수집기·타이머·DB는 없다. 이 제한을 UI와 도구 지침에 표시한다.

기존 기업 분석 화면과 같은 서비스 인스턴스·DB 작업 키·lease·정정 정책을 사용한다. AI는 DB 조회마다 요청 예산을 차감한다(스냅샷당 최대 2회). 동일 공개 조회 합치기 및 5초 메모리 캐시, 자격증명 범위 분리, 요청 취소/종료 시 추가 조회 거부를 적용한다. 캐시는 개인 계좌 정보를 담지 않는다.

## 도구와 한계

- `resolve_market_symbol`: 기존 공개 종목 검색 재사용. 중복 후보는 모델이 질문해 구분한다. 기업 매핑은 다음 DART 도구가 검증한다.
- `get_company_profile`: 종목코드→DART 기업코드 및 저장된 개요 기본 정보. 종목명으로 공시 본문을 추정하지 않는다.
- `get_company_disclosures`: 선택 기간·유형·페이지의 **제목·메타데이터**. 기존 정책인 날짜 차이 최대 365일, 페이지당 30건·최대 100페이지. 유형은 수신 페이지의 제목 분류이므로 원본 전체 건수/페이지는 모든 유형 기준이다. 다음 페이지·만료·제한 상태를 유지한다. 본문 미확보를 명시한다.
- `get_company_financials`: 최신 연간 최대 5개, 분기 최대 8개 저장 보고서, 요청당 지표 최대 4개. 회계연도·보고서 코드·기간 말·연결/별도·통화 기본 단위·접수번호·공시일·정정·원문·저장 시각 유지. 금액은 문자열이며 JS 부동소수 변환을 하지 않는다. 기본은 연간/단일분기 손익, 기말 재무상태. 누적 조회는 명시적 미지원이며 검증 없는 누적 차감·4분기 생성은 하지 않는다. 데이터 없는 계정은 null/사유를 유지한다.
- `get_company_business`: 기존 document.xml 파서가 저장한 사업보고서 일부 문단(사업/제품/수주/연구개발 최대 4영역×700자). 모델의 인용은 최대 300자 근거로 제한한다. 표·보고서 전체·임의 공시 본문 읽기는 지원하지 않는다.

같은 보고기간에는 접수번호가 가장 큰 정기보고서를 선택하며 기존 정정 검증/원문 접수번호 일치를 보존한다. 공시 목록은 기존 `last_reprt_at=Y`이다. 오래된 스냅샷은 partial이며 최신 정정 반영을 보장하지 않는다. 수집된 일부 문단이 있다는 이유로 다른 공시 원문까지 읽었다고 주장할 수 없다.

비교는 같은 계정 ID·통화·연결/별도·연간/같은 분기끼리만 BigInt 소수 계산한다. 증감액은 정확한 문자열, 증감률은 양수 기준값에 한해 소수 둘째 자리까지 절삭한다. 0·음수 기준값은 증감률 null과 사유를 반환한다. 독립적인 회계정책 일치·재작성 비교는 미검증이며 이 한계도 반환한다. 계정 ID가 다르거나 결측이면 억지로 맞추지 않는다.

## 관리자·평가·저장 호환성

`atlas-langgraph-research-v1`, 총괄 + 5개 전문 담당. 도구 목록에는 코드 등록, 운영 health 등록, 데이터 설정, 실제 최근 DB 정상 조회를 나눠 표시한다. 과거 수동 운영 확인 기록의 SHA/시각은 수정하지 않는다. 기존 평가 36개를 보존하고 고정 공시·재무 9개를 별도 seed로 추가한다. 사용자 사례 ID는 소유자·seed별로 결정되어 반복 등록을 방지한다. 코드 평가와 실제 모델 선택 품질을 구분한다.

기존 Supabase JSON 답변·단계·평가 저장 계약을 사용한다. **Supabase 추가 SQL 불필요.** 기존 SQL 재실행·기존 대화/평가/승인 카드/관심종목 초기화는 하지 않는다. 프런트는 새 서버가 오기 전 새 담당을 준비 미확인으로 표시한다. 잠금파일·운영 모델·unit·포트·환경변수 신규 변경 없음.

## 공식 사양 근거

- [DART 공시검색](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001): 접수 기간·페이지·최종 보고서·정정 표시. 본 앱의 30건/100페이지/365일 차이는 기존 앱 제한이다.
- [DART 전체 재무제표](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020): 연도·보고서 코드·연결/별도, 당기금액과 누적금액의 구분. 기존 `dartData`가 실제 확보한 필드만 사용한다.

실제 공급자 수신·운영 DB 내용·실제 OpenAI의 담당 선택은 로컬 고정 자료/모의 모델 테스트와 별개이며 VPS 배포 시 읽기 전용 smoke로 확인한다. `deploy/agent_research_smoke.js`는 모델·개인 데이터 변경·DART 신규 수집 없이 상태/메타데이터만 출력한다.
